Chapitre 08 - Require L Include

Fiche pratique : modularité, gabarits de pages, gestion des erreurs fatales et inclusion unique.

1. Pourquoi découper son code ?

La problématique du copier-coller

Sur un site de plusieurs dizaines de pages, l'en-tête (balise <head>, navigation), le pied de page et les configurations (connexion à la base de données, fonctions utilitaires) sont identiques. Si l'on copie-colle ce code dans chaque fichier, la moindre modification d'un lien dans le menu oblige à éditer l'ensemble des fichiers du site à la main. C'est une source d'erreurs majeure.

Le rôle des inclusions

PHP propose des structures de contrôle permettant d'insérer le contenu d'un fichier source dans un autre lors de l'exécution : include, require, include_once et require_once. Le serveur lit le fichier cible, interprète son éventuel code PHP et injecte son rendu à l'endroit exact de l'appel.

2. Comparatif : include vs require vs *_once

Le tableau suivant résume le comportement de chaque directive en cas de fichier introuvable et selon la fréquence d'inclusion souhaitée :

Instruction Comportement si absent Arrêt du script ? Cas d'usage recommandé
include Émet un avertissement (Warning : E_WARNING) Non (le script continue) Éléments secondaires non vitaux (bannière publicitaire, widget facultatif).
require Émet une erreur fatale (Fatal Error : E_COMPILE_ERROR) Oui (arrêt immédiat) Fichiers critiques indispensables (configuration, en-tête principal, sécurité).
include_once Avertissement (Warning). Vérifie si déjà chargé. Non Gabarits secondaires réutilisables sans risque de doublon d'affichage.
require_once Erreur fatale. Vérifie si déjà inclus dans le script. Oui Déclarations de fonctions, classes ou configurations (évite les erreurs de redéfinition).

Règle pratique : Par défaut, privilégiez toujours require pour vos fragments de pages (un design cassé sans header ne doit pas continuer à s'afficher) et require_once pour vos fichiers déclarant des fonctions ou des classes.

3. Syntaxe et gestion des chemins

Syntaxe formelle

Bien qu'on puisse les écrire avec des parenthèses comme des fonctions classiques, include et require sont des structures de langage. L'usage sans parenthèses est la convention la plus courante : 

<?php
// Syntaxe recommandée (sans parenthèses)
require 'header.php';

// Syntaxe tolérée (avec parenthèses)
include('footer.php');
?>

Sécuriser les chemins avec __DIR__

L'erreur classique consiste à utiliser des chemins relatifs simples ('header.php' ou '../header.php'). Ces chemins sont calculés par rapport au dossier de travail actuel de PHP, ce qui provoque des bugs dès qu'un script est appelé depuis un sous-dossier. La solution robuste consiste à utiliser la constante magique __DIR__ : 

<?php
// __DIR__ renvoie le chemin absolu du dossier contenant le fichier actuel
require_once __DIR__ . '/config/database.php';
require __DIR__ . '/layout/header.php';
?>

4. Cas pratique : modularisation d'un site web

Voici l'organisation recommandée pour découper un site standard :

mon-site/
├── layout/
│   ├── header.php       # En-tête HTML commun et menu de navigation
│   └── footer.php       # Pied de page HTML et scripts JavaScript
├── contact.php          # Page de contact
└── index.php            # Page d'accueil

Le fichier layout/header.php

Ce fichier contient le début du balisage HTML. Il peut également exploiter des variables dynamiques définies dans la page appelante, comme le titre de la page : 

<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title><?= $titre ?? 'Mon Site Web' ?></title>
    <link rel="stylesheet" href="/assets/style.css">
</head>
<body>
    <header>
        <nav>
            <a href="index.php">Accueil</a>
            <a href="contact.php">Contact</a>
        </nav>
    </header>
    <main>

Le fichier layout/footer.php

Ce fichier ferme les balises principales et ajoute les crédits ainsi que la date dynamique générée par PHP : 

    </main>
    <footer>
        <p>&copy; <?= date('Y') ?> - Tous droits réservés.</p>
    </footer>
</body>
</html>

La page principale index.php

La page d'accueil définit ses paramètres propres, puis assemble les fragments avec require : 

<?php
$titre = "Accueil - Bienvenue";
require __DIR__ . '/layout/header.php';
?>

<h1>Bienvenue sur notre plateforme</h1>
<p>Ce contenu est propre à la page d'accueil. L'en-tête et le pied de page sont gérés de façon centralisée.</p>

<?php
require __DIR__ . '/layout/footer.php';
?>

5. Le piège classique : redéclaration de fonction

En PHP, il est strictement interdit de déclarer deux fonctions portant le même nom. Si vous utilisez require pour importer un fichier contenant des fonctions personnalisées, et que ce fichier se retrouve appelé deux fois (directement ou indirectement par un autre module), PHP déclenche une erreur fatale Cannot redeclare function.

C'est la raison d'être de require_once : PHP mémorise les fichiers déjà analysés et ignore l'appel s'il a déjà été traité. 

<?php
// functions.php
function saluer(string $nom): string {
    return "Bonjour " . $nom;
}

// index.php
require_once __DIR__ . '/functions.php';
require_once __DIR__ . '/functions.php'; // Ignoré sans générer d'erreur fatale

echo saluer("Alice");
?>
