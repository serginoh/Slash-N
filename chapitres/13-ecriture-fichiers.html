Chapitre 13 - Écriture-fichiers

1. Qu'est-ce qu'une session et pourquoi l'utiliser ?

La nature « sans état » (stateless) du protocole HTTP

Le protocole HTTP ne retient rien entre deux requêtes. Dès qu'un utilisateur clique sur un lien ou change de page, le serveur web oublie qui il est. Pour concevoir un espace membre, retenir un panier d'achat ou afficher un message temporaire (flash message), le serveur doit disposer d'un moyen fiable de lier plusieurs requêtes successives à un même internaute.

Le rôle de la session

La session permet de conserver des données relatives à un utilisateur d'une page à l'autre tout au long de sa navigation. Contrairement aux cookies bruts, les données de session sont stockées exclusivement sur le serveur. L'utilisateur ne peut donc ni lire, ni altérer, ni falsifier les données stockées (par exemple, un statut administrateur ou un solde).

2. Comparatif : Session vs Cookie

Pour bien comprendre l'architecture web, voici la distinction fondamentale entre un Cookie et une Session :

Critère Cookie ($_COOKIE) Session ($_SESSION)
Lieu de stockage Sur le poste client (navigateur) Sur le disque ou la mémoire du serveur
Sécurité & intégrité Faible : modifiable et consultable par l'utilisateur (ou via scripts) Élevée : stocké côté serveur, inaccessible au visiteur
Volume de données Limité à environ 4 Ko par domaine Virtuellement illimité (selon configuration serveur)
Cas d'usage type Mémoriser un choix de thème sombre, consentement RGPD Connexion utilisateur (auth), panier d'achats, permissions

Le lien indissociable entre cookie et session : Pour associer un visiteur à son fichier de session côté serveur, PHP dépose automatiquement sur le navigateur un cookie unique appelé PHPSESSID. Ce cookie ne contient aucune donnée personnelle, seulement un identifiant aléatoire (ex. 'a1b2c3d4...'). À chaque requête, le navigateur transmet ce token, et PHP recharge le fichier de session correspondant.

3. Démarrer et manipuler une session

Règle d'or : session_start() avant tout envoi

La fonction session_start() initialise ou reprend une session existante. Elle envoie des en-têtes HTTP (Set-Cookie). Elle doit donc impérativement être appelée avant tout affichage HTML, espace ou saut de ligne, sous peine de déclencher l'erreur classique Headers already sent.

Écrire, lire et vérifier des données dans $_SESSION

Une fois la session ouverte, la superglobale associative $_SESSION s'utilise exactement comme un tableau PHP standard : 

<?php
// Toujours démarrer la session en premier
session_start();

// 1. Écriture de données simples et complexes
$_SESSION['user_id'] = 42;
$_SESSION['nom'] = 'Dupont';
$_SESSION['role'] = 'admin';
$_SESSION['panier'] = ['article_id' => 12, 'quantite' => 2];

// 2. Vérification et lecture
if (isset($_SESSION['user_id'])) {
    echo "Bienvenue, " . htmlspecialchars($_SESSION['nom']) . " !";
} else {
    echo "Vous n'êtes pas connecté.";
}
?>

Supprimer une variable ou détruire la session

Pour déconnecter un utilisateur ou vider le panier, plusieurs approches existent selon le besoin : 

<?php
session_start();

// Supprimer UNE seule variable spécifique
unset($_SESSION['panier']);

// Déconnexion complète et propre :
// 1. Vider le tableau en mémoire
$_SESSION = [];

// 2. Détruire le cookie de session sur le navigateur
if (ini_get("session.use_cookies")) {
    $params = session_get_cookie_params();
    setcookie(session_name(), '', time() - 42000,
        $params["path"], $params["domain"],
        $params["secure"], $params["httponly"]
    );
}

// 3. Supprimer le fichier de stockage sur le serveur
session_destroy();
?>

4. Sécurité renforcée des sessions en PHP 8.x

Dans les versions modernes de PHP, la sécurisation des sessions ne doit pas être laissée aux réglages par défaut. Voici les deux impératifs de sécurité :

1. Démarrage sécurisé avec options (PHP 7.3+ / 8.x)

Plutôt que de modifier php.ini, PHP permet de passer un tableau d'options directement dans session_start(). Cela bloque les attaques XSS (vol de session par script JavaScript) et protège contre le vol de session lors de requêtes inter-sites (CSRF) : 

<?php
session_start([
    'cookie_httponly' => true,      // Empêche JavaScript de lire le cookie (anti-XSS)
    'cookie_secure'   => true,      // Transmet le cookie uniquement via HTTPS (en prod)
    'cookie_samesite' => 'Strict',  // Empêche l'envoi du cookie depuis un site tiers (anti-CSRF)
    'use_only_cookies'=> true,      // Interdit le passage de session_id dans l'URL
    'cookie_lifetime' => 0          // Expire à la fermeture du navigateur
]);
?>

2. Régénération de l'ID contre la fixation de session

Une attaque courante appelée Session Fixation consiste pour un pirate à imposer un ID de session à une victime avant qu'elle ne s'authentifie. Dès qu'un utilisateur valide ses identifiants avec succès, vous devez impérativement régénérer son identifiant de session : 

<?php
// Lors de la validation réussie des identifiants (login) :
session_regenerate_id(true); // 'true' supprime immédiatement l'ancien fichier de session
$_SESSION['user_id'] = $utilisateur['id'];
?>

5. Cas pratique : Authentification et protection de page

Voici l'enchaînement standard d'un système de connexion sécurisé combinant les inclusions et les sessions :

Fichier login.php (Connexion)

<?php
session_start(['cookie_httponly' => true, 'cookie_samesite' => 'Strict']);

$erreur = null;
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $login = $_POST['username'] ?? '';
    $mdp   = $_POST['password'] ?? '';

    // Vérification simplifiée (à coupler avec password_verify en production)
    if ($login === 'admin' && $mdp === 'secret123') {
        session_regenerate_id(true);
        $_SESSION['user'] = ['username' => 'admin', 'role' => 'administrator'];
        header('Location: admin.php');
        exit;
    } else {
        $erreur = "Identifiants invalides.";
    }
}
?>
<!-- Formulaire de connexion HTML classique -->

Fichier admin.php (Page protégée)

<?php
session_start();

// Vérifier si l'utilisateur est authentifié
if (!isset($_SESSION['user'])) {
    header('Location: login.php');
    exit; // Toujours stopper l'exécution après une redirection
}
?>
<!DOCTYPE html>
<html lang="fr">

    <meta charset="UTF-8">
    <title>Zone Privée</title>


    <h1>Tableau de bord</h1>
    <p>Bonjour <?= htmlspecialchars($_SESSION['user']['username']) ?>, vous êtes connecté.</p>
    <p><a href="logout.php">Se déconnecter</a></p>

</html>
