Chapitre 10 - Traitement-Formulaires

1. La problématique : répétition du balisage HTML

Le constat du code verbeux

Dans une application web classique, l'écriture manuelle des formulaires devient rapidement fastidieuse et redondante. Chaque champ requiert généralement une structure complète : une balise conteneur (ex. <div> ou <p>), un label avec son attribut for, un champ <input> avec ses attributs (type, name, id, class), sans oublier l'injection manuelle de la valeur déjà saisie pour ne pas forcer l'utilisateur à tout retaper en cas d'erreur.

La solution : automatiser avec la Programmation Orientée Objet (POO)

Pour respecter le principe DRY (Don't Repeat Yourself), nous créons un composant d'aide aux formulaires (une classe Form). Cette classe centralise le formatage HTML commun, applique les styles de façon uniforme (ex. classes Bootstrap, Tailwind ou CSS maison) et gère automatiquement la réinjection des valeurs soumises ($_POST ou données d'une entité).

2. Comparatif : Formulaire manuel vs Générateur d'objet Form

Le tableau suivant met en regard les contraintes de l'écriture HTML brute et les gains apportés par une classe dédiée :

Critère Écriture HTML manuelle Classe Form (POO PHP 8)
Volume de code Lourd et verbeux (5 à 8 lignes de balises par champ) Ultra-concis : 1 ligne PHP par champ ($form->input(...))
Modification du design Fastidieuse : nécessite de retoucher chaque fichier de vue Immédiate : une seule méthode surround à modifier dans la classe
Pré-remplissage des valeurs Complexe et répétitif (conditions ternaires, htmlspecialchars) Automatisé : extraction transparente de $data[$key] sécurisée
Maintenance & robustesse Risque élevé d'oubli de balises fermantes ou de sécurité XSS Robuste, typé strictement et sécurisé de façon centralisée

Principe clé : La classe Form agit comme un filtre d'assemblage : vous lui confiez des données brutes, et elle produit du balisage HTML propre, stylisé et sécurisé.

3. Conception de la classe Form (PHP 8.x)

En exploitant les fonctionnalités modernes de PHP 8 (promotion de propriétés dans le constructeur, typage strict, paramètres optionnels), la classe reste compacte, lisible et parfaitement extensible : 

<?php
declare(strict_types=1);

class Form
{
    /**
     * Balise HTML entourant chaque champ (div, p, etc.)
     */
    public string $surround = 'div';

    /**
     * Le constructeur utilise la promotion de propriété (PHP 8.0+)
     * Il reçoit les données initiales (ex: $_POST ou tableau d'enregistrements)
     */
    public function __construct(private array $data = [])
    {
    }

    /**
     * Entoure un contenu HTML de la balise définie dans $surround
     */
    private function surround(string $html): string
    {
        return "<{$this->surround} class=\"form-group mb-3\">{$html}</{$this->surround}>";
    }

    /**
     * Récupère la valeur d'un champ ou retourne une chaîne vide
     */
    private function getValue(string $name): string
    {
        return (string)($this->data[$name] ?? '');
    }

    /**
     * Génère un champ input avec son label associé
     */
    public function input(string $name, string $label, string $type = 'text'): string
    {
        $valeur = htmlspecialchars($this->getValue($name), ENT_QUOTES, 'UTF-8');
        
        $html = "<label for=\"{$name}\" class=\"form-label\">{$label}</label>";
        $html .= "<input type=\"{$type}\" name=\"{$name}\" id=\"{$name}\" class=\"form-control\" value=\"{$valeur}\">";
        
        return $this->surround($html);
    }

    /**
     * Génère une zone de texte multi-lignes (<textarea>)
     */
    public function textarea(string $name, string $label, int $rows = 4): string
    {
        $valeur = htmlspecialchars($this->getValue($name), ENT_QUOTES, 'UTF-8');
        
        $html = "<label for=\"{$name}\" class=\"form-label\">{$label}</label>";
        $html .= "<textarea name=\"{$name}\" id=\"{$name}\" rows=\"{$rows}\" class=\"form-control\">{$valeur}</textarea>";
        
        return $this->surround($html);
    }

    /**
     * Génère le bouton d'envoi du formulaire
     */
    public function submit(string $texte = 'Envoyer'): string
    {
        return $this->surround("<button type=\"submit\" class=\"btn btn-primary\">{$texte}</button>");
    }
}
?>

4. Utilisation concrète dans un script de traitement

Voyons comment cette classe simplifie radicalement une page PHP combinant traitement de soumission et affichage de formulaire : 

<?php
require_once __DIR__ . '/Form.php';

// Initialisation avec les données reçues si le formulaire a été soumis
$form = new Form($_POST);

$messageConfirmation = null;

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $nom   = trim($_POST['username'] ?? '');
    $email = trim($_POST['email'] ?? '');

    // Exemple de validation basique
    if (!empty($nom) && filter_var($email, FILTER_VALIDATE_EMAIL)) {
        $messageConfirmation = "Merci " . htmlspecialchars($nom) . ", vos informations sont enregistrées.";
        // On réinitialise le formulaire après succès
        $form = new Form();
    }
}
?>
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title>Inscription rapide</title>
    <!-- Exemple avec Bootstrap pour la mise en page -->
    <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.0/dist/css/bootstrap.min.css" rel="stylesheet">
</head>
<body class="p-5">
    <div class="container" style="max-width: 500px;">
        <h1 class="mb-4">Créer un compte</h1>

        <?php if ($messageConfirmation): ?>
            <div class="alert alert-success"><?= $messageConfirmation ?></div>
        <?php endif; ?>

        <form action="" method="post">
            <?= $form->input('username', 'Nom d\'utilisateur') ?>
            <?= $form->input('email', 'Adresse email', 'email') ?>
            <?= $form->input('password', 'Mot de passe', 'password') ?>
            <?= $form->textarea('bio', 'Biographie / Remarques') ?>
            <?= $form->submit('Valider mon inscription') ?>
        </form>
    </div>
</body>
</html>

5. Évolution : personnalisation et héritage

L'intérêt majeur de la POO est la capacité d'adapter le rendu sans réécrire la logique. Par exemple, si vous changez de framework CSS (passage de Bootstrap à Tailwind CSS, ou formulaire horizontal), il suffit d'étendre la classe initiale : 

<?php
class TailwindForm extends Form
{
    public function input(string $name, string $label, string $type = 'text'): string
    {
        $valeur = htmlspecialchars($this->getValue($name), ENT_QUOTES, 'UTF-8');
        
        $html = "<label for=\"{$name}\" class=\"block text-sm font-medium text-gray-700\">{$label}</label>";
        $html .= "<input type=\"{$type}\" name=\"{$name}\" id=\"{$name}\" value=\"{$valeur}\" class=\"mt-1 block w-full rounded-md border-gray-300 shadow-sm focus:border-indigo-500 focus:ring-indigo-500\">";
        
        return "<div class=\"mb-4\">{$html}</div>";
    }
}
?>

6. Règles de sécurité à ne jamais oublier

  1. Échappement systématique des valeurs : Toute valeur réinjectée dans un attribut HTML (value="...") doit obligatoirement passer par htmlspecialchars($valeur, ENT_QUOTES, 'UTF-8'). Cela neutralise l'injection de balises de script et bloque les attaques XSS.
  2. Méthode HTTP et CSRF : Tout formulaire modifiant des données doit impérativement être envoyé via la méthode POST. En production, pensez à ajouter un champ caché avec un jeton CSRF stocké en session pour empêcher les requêtes frauduleuses externes.
